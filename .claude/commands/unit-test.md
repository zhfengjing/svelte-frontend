# 单元测试生成

为指定文件或模块生成单元测试代码。

## 使用方式

```
/unit-test [文件路径或模块名]
```

**示例：**
- `/unit-test src/services/api.js`
- `/unit-test src/services/request.js`
- `/unit-test ArticleCard`

---

## 执行步骤

1. 读取目标文件内容，理解其功能、导出的函数/方法和数据结构
2. 分析以下测试维度：
   - **正常路径**：输入合法参数时的预期输出
   - **边界条件**：空值、null、undefined、极端数值
   - **异常路径**：网络错误、非法参数、权限不足等
   - **副作用**：状态变更、API 调用、事件触发
3. 基于项目技术栈（Svelte + Vite）选择合适的测试框架（推荐 Vitest）
4. 生成完整测试文件，放置于与源文件同目录的 `__tests__` 文件夹或 `*.test.js` 同名文件

## 测试生成规范

- 每个函数/方法至少覆盖：1 个正常用例 + 1 个边界用例 + 1 个异常用例
- API 相关函数需 mock `axios` 或 `fetch`
- Svelte 组件测试需验证渲染输出、Props、事件绑定
- 测试描述使用中文，清晰说明被测场景
- 使用 `describe` 按模块分组，`it` / `test` 描述具体场景

## 输出格式

生成测试文件后：
1. 展示完整测试代码
2. 说明每个测试块的覆盖意图
3. 如需安装依赖（如 `vitest`、`@testing-library/svelte`），列出安装命令

---

请读取 `$ARGUMENTS` 对应的源文件，然后按照以上规范生成单元测试。
